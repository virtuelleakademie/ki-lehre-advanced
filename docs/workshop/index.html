Building Diagnostic AI Tools, Grounded in Cognitive Load Theory

A 3-hour workshop on implementing CLT principles in a working diagnostic tool, without writing code

Workshop Overview

A 3-hour workshop in which participants build a CLT-grounded diagnostic AI tool for their own discipline. The output schema is fixed; participants iterate the system prompt. They never write code, never edit data structures, and never deploy anything themselves.

Participants leave with two artifacts: a configured tool URL with their prompt baked in, and a portable prompt recipe usable in Microsoft Copilot, ChatGPT, or Claude.

What You’ll Do

  1. See the diagnostic shell in action: a working tool that classifies student responses into five CLT-grounded categories
  2. Pick a discipline scenario from a set of six, each with three calibrated student responses
  3. Write a system prompt that teaches the LLM how the CLT taxonomy shows up in your discipline
  4. Test, iterate, export: run on calibrated responses, refine, then export a portable prompt for any LLM interface

What You’ll Build

A diagnostic tool that takes a student response (written work, a short answer, an explanation) and returns:

  • A Diagnosis containing one of five load_signal categories, the evidence for that classification, a severity rating, and discipline-specific notes
  • A Response containing one of five intervention categories and a concrete piece of text to say to the student

The five load_signal categories are derived from cognitive load theory and schema-acquisition research: intrinsic_overload, extrinsic_distractor, germane_disengagement, schema_gap, active_misconception. They are fixed across all disciplines. Your discipline expertise lives in the system prompt.

Learning Objectives

By the end of this workshop, you will:

  1. Identify five CLT-grounded diagnostic signals in student work
  2. Match each diagnostic signal to a corresponding intervention strategy
  3. Write a system prompt that instructs an LLM to apply those categories in your discipline
  4. Calibrate a diagnostic prompt against tagged student responses to know where to trust it and where to second-guess it
  5. Produce a portable prompt recipe usable in any LLM interface you have access to

Pedagogical Foundation

This workshop applies Cognitive Load Theory (Sweller 1988) (with the updated germane-processing framing in Sweller, Ayres and Kalyuga 2019) and schema-acquisition research (Kalyuga 2009) to the practical problem of reading student work.

The five diagnostic categories correspond to the cognitive architecture CLT describes:

  • intrinsic_overload and extrinsic_distractor map onto the classical intrinsic and extraneous load types
  • germane_disengagement flags the absence of germane processing
  • schema_gap and active_misconception extend the framework to two distinct schema-acquisition failure modes (absent schema vs. wrong schema)

The decomposition matters because each category implies a distinct intervention. Diagnostic precision drives instructional choice.

Prerequisites

Required Knowledge

  • None technical. Participants do not write code, edit data structures, or run notebooks.
  • Some teaching experience in any discipline. The workshop’s central activity is reading a student response and asking what cognitive signal it reveals.

Materials Required

Setup before the workshop

What you need:

  1. A laptop with a modern browser
  2. An internet connection (the diagnostic shell runs on Hugging Face Spaces)
  3. Optional but useful: a notebook or document where you can paste your final exported prompt

What you do not need:

  • Python, an IDE, or a development environment
  • An API key for any LLM
  • A Hugging Face account
  • Any preparation reading

Workshop Structure: An Applied Worked Example

ImportantThis Workshop IS a Worked Example

This workshop demonstrates the principle it teaches by being structured as a worked example of CLT-grounded design.

Traditional approach (problem-solving):

Define your tool’s data structures, design the schema, implement the LLM call, build a UI, deploy.

This is too much for a 3-hour workshop and not what most participants need to know.

This approach (worked example):

The structure is given. The intelligence lives in the prompt. Your work is making the structure speak your discipline’s language.

Why? The decomposition (theory provides structure, practitioner provides cues) is the move we want participants to take back to their teaching with AI. Doing it once at workshop scale lets participants feel the leverage.

Meta-learning moment

As you progress through today, notice when the fixed schema is helping you think and when it feels constraining. Notice the categories you found easy to instantiate in your discipline and the ones that required real effort. The categories that required effort are usually the ones your teaching most needs help diagnosing.

Technical Stack

You do not need to know any of this. It is documented for instructors and for the curious.

  • Anthropic Claude Haiku 4.5: structured-output language model used by the diagnostic shell
  • Pydantic: defines the fixed Diagnosis and Response schema in models.py
  • Gradio: hosts the three-surface shell UI
  • Hugging Face Spaces: free deployment for the shell

Connection to the Trilogy

This is the advanced workshop in a three-workshop sequence on AI in education at the BFH Virtuelle Akademie:

  • The beginner workshop introduces AI in education broadly.
  • The intermediate workshop establishes cognitive load theory, the offloading-vs-outsourcing distinction, and a diagnostic vocabulary for analysing assignments.
  • This advanced workshop turns that diagnostic vocabulary into a working tool.

If you have not done the intermediate workshop, this workshop will still work for you, but the theory section will move quickly through the CLT background that workshop establishes more carefully.
