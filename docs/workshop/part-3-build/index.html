Overview

In this section, we’ll build the core of our application:

  1. A concept library defining what we can teach in each domain
  2. An AI agent configured to generate pedagogically sound examples
  3. A generation function that connects profiles to examples
  4. Testing to verify quality

Activity 1: Create the Concept Library

Note💻 Live Coding (10 minutes)

We’ll build this together. The instructor codes while explaining the structure.

What Is a Concept Library?

The concept library defines what we can teach in each domain. For each concept, we specify:

  • name: What the concept is called
  • abstract: General description (domain-independent)
  • difficulty: Skill level required
  • typical_use: When/why to use this concept

Activity 2: Design the System Prompt

Note🧠 Critical Discussion (20 minutes)

Before coding, let’s think: What instructions should we give the AI to generate good worked examples?

What Makes a Good Personalized Example?

Note💭 Facilitated Discussion

Instructor asks: “What instructions would help the AI generate examples that…”

Collect responses and synthesize:

DO:

✅ Weave interests naturally (not tacked on)

✅ Use learner’s name throughout

✅ Make data realistic and believable

✅ Match complexity to learner’s level

✅ Show every step explicitly

✅ Connect to their goal

DON’T:

❌ Create generic examples with personal details superficially added

❌ Force artificial connections

❌ Use too much jargon for beginners

❌ Use abstract variable names

❌ Skip steps in solutions

The System Prompt

The system prompt is critical for quality. It’s our pedagogical guidance to the AI.

from openai import OpenAI

# Initialize the client
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# Define our pedagogical system prompt
SYSTEM_PROMPT = """You are an expert educator who creates highly personalized
worked examples that connect abstract concepts to learners' lived experiences.

CRITICAL INSTRUCTIONS:

1. Weave the learner's interests, hobbies, and goals naturally into the example
2. Use their name throughout to increase personal connection
3. Make data and scenarios feel authentic to their context
4. Keep explanations clear but connect to what they care about
5. The example should feel like it was written specifically for this person
6. Match complexity to their level (beginner/intermediate/advanced)
7. Make the connection to their goal explicit and motivating
8. Use concrete numbers and realistic data
9. For programming examples, include actual runnable code with comments
10. For quantitative examples, show all calculations step by step

STRUCTURE YOUR EXAMPLES:

- Start with an engaging title that mentions their interest
- Frame the problem in their context (use their name and interests)
- Present data that feels real to their situation
- Walk through steps clearly with explanations
- For code: include comments explaining each part
- For math: show each calculation explicitly
- Connect the final answer to their goal
- Suggest a related practice problem in their context

AVOID:

- Generic examples with personal details superficially added
- Forced or artificial connections
- Too much technical jargon for beginners
- Abstract variable names (use meaningful names from their context)
- Skipping steps in solutions

Remember: This is a WORKED EXAMPLE - a complete solution for the learner
to study, not a problem for them to solve.
"""

Why Each Instruction Matters

Tip💡 Pedagogical Grounding
Instruction Cognitive Science Rationale
“Weave interests naturally” Reduces extraneous load, authentic context
“Use their name” Personal connection → germane load (motivation)
“Authentic data” Believability → mental simulation → deeper encoding
“Match complexity to level” Zone of proximal development
“Show all steps” Schema construction requires seeing the pattern
“Connect to goal” Motivation, relevance, transfer

The “avoid” list addresses common failure modes we’ve observed in testing.

Activity 3: Create the Generation Function

Note💻 Live Coding (10 minutes)

Now we connect everything together.

The Generation Function

This function takes a learner profile and a concept, then asks the AI to generate a personalized example.

def generate_personalized_example(
    profile: LearnerProfile,
    concept: dict
) -> PersonalizedWorkedExample:
    """Generate a personalized worked example using GPT-5.1"""

    # Build the user prompt with learner and concept information
    user_prompt = f"""
    Create a worked example for:

    LEARNER PROFILE:
    - Name: {profile.name}
    - Domain: {profile.domain}
    - Specific interest: {profile.specific_interest}
    - Hobby/passion: {profile.hobby_or_passion}
    - Goal: {profile.goal}
    - Level: {profile.background_level}

    CONCEPT TO TEACH:
    - Name: {concept['name']}
    - Abstract description: {concept['abstract']}
    - Difficulty: {concept['difficulty']}
    - Typical use: {concept['typical_use']}

    Create a worked example that teaches this concept using {profile.name}'s
    specific context. The example should feel personal and relevant to their
    goal of "{profile.goal}".

    Make the problem realistic and the data believable for their situation.

    For programming: Include complete, runnable code with explanatory comments.
    For quantitative problems: Show every calculation step explicitly.

    This is a WORKED EXAMPLE - provide the complete solution for them to study.
    """

    # Call GPT-5.1 with structured output
    response = client.responses.parse(
        model="gpt-5.1",
        input=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_prompt}
        ],
        text_format=PersonalizedWorkedExample
    )

    # Return the parsed, validated example
    return response.output_parsed

Why This Works

The function:

  1. Combines profile information with concept description
  2. Provides context to the AI about the learner
  3. Uses structured outputs - GPT-5.1 guarantees the response matches PersonalizedWorkedExample
  4. Returns validated data ready to use in your application
  5. Simple and transparent - No complex framework needed

    domain="programming",
    specific_interest="web development",
    hobby_or_passion="baking",
    goal="build a recipe sharing website",
    background_level="beginner"

Quality Discussion

Note💬 Group Discussion

Questions to facilitate:

  1. Is it personalized?
    • Does it genuinely use Sarah’s context, or is “baking” just tacked on?
    • Would Sarah find this relevant?
  2. Is it pedagogically sound?
    • Are all steps shown?
    • Is the complexity appropriate for a beginner?
    • Can Sarah study this and learn the pattern?
  3. What could be improved?
    • Too much jargon?
    • Skipped steps?
    • Forced connections?
  4. Would this work at scale?
    • Generate 2-3 more for different profiles
    • Observe consistency and quality
