Spec Sheets bauen, mit LLMs als Hypothesengenerator und Lernende-Simulator

KI in der Lehre: Advanced — Workshop-Slides

Andrew Ellis

10 May, 2026

Drei Stunden, ein Spec Sheet, ein getesteter System-Prompt.


Die zentrale didaktische Arbeit beim KI-Einsatz liegt nicht im Schreiben von Prompts, sondern in der Spezifikation dessen, was im Kopf einer Lernerin tatsächlich vorgeht.

Begrüssen, Workshop-Programm in einem Satz: “Wir bauen heute ein Spec Sheet für eine deiner Aufgaben, übersetzen es in einen System-Prompt und testen es einmal.” Pausen-Hinweis. Direkt in den Einstieg.

Was du heute tust


Block 1 (45 min)

Worked Example beobachten

CLT-Auffrischung, dann gemeinsamer Durchgang durch ein ausgearbeitetes Spec Sheet.

Block 2 (60 min)

Eigenes Spec Sheet bauen

Für eine Teilaufgabe deiner Lehre: Wissensbausteine, Fehlkonzepte, Pruning.

Block 3 + Closing (38 min)

Spec → Prompt → Test

Übersetzen, testen, taggen für KI-Substitution, Verpflichtung.


Programmiererfahrung brauchst du nicht. Eine Aufgabe aus deiner Lehre solltest du parathaben.

Block 1: Theorie und Beispiel

Cognitive Load Theory: der Engpass

Das Arbeitsgedächtnis verarbeitet etwa 4 Elemente gleichzeitig, für 15-30 Sekunden.

Diese Engstelle ist der Grund, warum Lernen Mühe macht. Keine Technologie umgeht sie.

~1.5 Min. Auf den Engpass im Diagramm zeigen: links breit, Mitte schmal (4 Elemente / 15-30 Sek.), rechts wieder breit. Fluss von links nach rechts. Keine Technologie umgeht diese Engstelle.

Vorwissen bestimmt die Last

Dieselbe Aufgabe ist für Anfängerinnen und Fortgeschrittene unterschiedlich kostenintensiv.


Aufgabe: Löse nach \(x\) auf: \[-1(-x - 7) = 14x - 6\]

Anfängerin

Hohe intrinsische Last:

  • Was bedeutet das Minus vor der Klammer?
  • Wie verteile ich?
  • Welche Rechenregeln gelten?

Fortgeschrittene

Niedrige intrinsische Last:

  • “Klammer auflösen” → Schema
  • “Terme zusammenfassen” → Schema
  • “Nach \(x\) auflösen” → Schema


Konsequenz: Aufgaben müssen sich an Vorwissen anpassen. Das verlangt Diagnose.

~1.5 Min. Gleiche Gleichung, völlig verschiedene Kosten. Konsequenz: ein Übungsblatt für alle ist für die meisten falsch. Brücke: Aufgaben müssen sich an Vorwissen anpassen, das verlangt Diagnose.

Scaffolding-Leiter (Fading)

Wenn die intrinsische Last zu hoch ist, brauchen Lernende gezieltes Scaffolding.


Stufe Format Geeignet, wenn…
1 Worked Example: vollständig durchgearbeitet Baustein noch gar nicht da
2 Completion Problem: teilweise gelöst Baustein teilweise da
3 Hinweis-gestützt: nur strategische Hinweise Baustein da, aber unsicher
4 Eigenständig: ohne Unterstützung Baustein zuverlässig da


Welche Stufe für welchen Baustein passt, hängt von der Diagnose des Vorwissens ab.

~1.5 Min. Die Stufen-Leiter ist Standard CLT/Sweller. Welche Stufe greift, hängt von der Diagnose ab. Brücke: heute machen wir die Diagnose explizit.

Heute: die Diagnose explizit machen


Die CLT sagt: wir müssen das Vorwissen diagnostizieren, sonst passt das Scaffolding nicht.

Heute machen wir diese Diagnose explizit, schriftlich, falsifizierbar.

Die disziplinierte Form dieser Diagnose ist das Spec Sheet.

~1 Min. Das ist die Brücke. CLT sagt: diagnostizieren! Heute: wir schreiben die Diagnose explizit auf. Das ist das Spec Sheet. Lange Pause hier; das ist der Kerngedanke.

Drei Wissensbaustein-Typen

Nicht alle Wissensformen werden gleich erworben. Die Typ-Unterscheidung macht sichtbar, welche Aktivität welche Wissensform überhaupt entwickeln kann.

Diese drei Typen kommen in deinem Spec Sheet (Sektion B) explizit vor.

~2 Min. Drei Typen, drei Erwerbsmechanismen. Pointe: nicht alles ist “Erklärung anhören”; jede Wissensform verlangt eine andere Aktivität, sonst entsteht der Baustein nicht. Wichtige Unterscheidung für das Closing (Selbst-Tun vs. Zuschauen).

Spec ist dauerhaft, Prompt ist Übersetzung

Spec Sheet bleibt; der Prompt wird für jede Modellgeneration neu gerendert. Block 3 macht die Trennung an deinem eigenen Material erlebbar.

~1 Min. Pragmatische Trennung. Auf das Diagramm zeigen: oben durchgehend Spec, unten diskrete Prompts pro Modellgeneration. Ein Prompt, den du heute schreibst, kann in zwei Jahren obsolet sein, das Spec Sheet nicht.

Zwei LLM-Rollen heute


Hypothesengenerator

Das LLM schlägt Wissensbausteine vor.

Du prüfst und markierst V (vermutet) oder B (beobachtet) oder verwirfst.

→ Vor der Validierung.

Lernende-Simulator

Das LLM spielt eine Studierende ohne Baustein X.

Zwei Probemodi:

  • Reaktiv: liest dein Material, meldet was unklar ist
  • Produktiv: schreibt eine Antwort mit Fehlkonzept


Beim Arbeiten in Block 2 immer fragen: In welcher Rolle ist das LLM gerade?

~1 Min. Zwei klar getrennte Rollen. Mehr als das brauchen wir heute nicht.

Drei Affordance-Typen (kurz)

Werkzeuge wechseln, Affordance-Typen bleiben:


Chat-Werkzeug

Copilot, ChatGPT, HuggingChat.

System-Prompt + Eingabe + Antwort.

→ Block 3 nutzt Typ 1.

Strukturierte API

z.B. Marimo + Pydantic.

Erzwungenes Ausgabe-Schema.

→ Live-Demo (1 Min).

Agentisch

Claude Code, pi.dev.

LLM mit Werkzeugzugriff.

→ Volllänge im Nachlesen.


Dein Spec Sheet ist für alle drei Typen verwendbar. Nur die Übersetzung ändert sich.

~3 Min insgesamt für die Tour. Marimo-Demo: 6 Zellen Pydantic-Schema, ca. 1 Min. Agentisches Werkzeug: nur kurz nennen, Volllänge im Nachlesen.

Block 2: dein eigenes Spec Sheet

Block 2 in 60 Min


Zeit Schritt
5 min Vorlage öffnen, Teilaufgabe wählen, Sektion A ausfüllen
25 min Wissensbausteine inventarisieren (Prompt 1) → validieren V/B/Korrigieren/Verwerfen → Lernaktivitäten (Prompt 2)
20 min Reaktive Simulation (Prompt 3) → Funde zurück in Sektion B; Produktive Simulation (Prompt 4) → Sektion C
10 min Paar-Feedback (3 strukturierte Fragen)


Ziel: erste vollständige Version. Nicht perfekt. Nicht alle Felder.

~30 Sek Folie. Kurz orientieren, dann gehen die Teilnehmenden in die Eigenarbeit. Blockfolie, kein Lehrinhalt.

Block 3: Spec → Prompt → Test

Spec → Prompt ist mechanisch


Aus deinem Spec Sheet

  • Sektion B (Wissensbausteine, gruppiert nach Typ)
  • Sektion C (Fehlkonzepte, in Ich-Form)
  • “Was schiefgeht”-Sätze pro Baustein

Wird zum System-Prompt

  • “Wissensbausteine, die diese Teilaufgabe verlangt: […]”
  • “Wahrscheinliche Fehlkonzepte: […]”
  • Verbote (“erfinde nichts ausserhalb dieser Listen”)


Wo dein Spec vage ist, fällt der Prompt schwer. Genau das ist die Lehre aus Block 3.

~2 Min. Mechanik vorführen am Statistik-Beispiel aus Block 1. Die Stelle hervorheben, an der eine Klammer im Template noch nicht im Spec Sheet abgedeckt ist.

Test-Protokoll: drei mögliche Ausgänge

Wähle einen Baustein aus deiner Spec, den du als B (beobachtet) markiert hast. Gib die zugehörige Studierenden-Antwort ans Werkzeug.

Pass / Fail soft / Fail hard. Zwei der drei Ausgänge führen zurück: Fail soft zum Spec Sheet, Fail hard zum Prompt.

~2 Min. Auf das Diagramm zeigen. Drei Branches sind die drei klaren Pass/Fail-Kriterien; die zwei gestrichelten Pfeile sind die Rückkopplungen — Fail soft ist Spec-Diagnose, Fail hard ist Prompt-Diagnose. Übergang in 15 min Eigenarbeit.

Closing

Falsifikationsnotiz: was würde dich widerlegen?


Wähle einen Wissensbaustein aus Sektion B, den du als zentral einschätzt.

Schreibe einen Satz: welches Verhalten von Studierenden würde dir zeigen, dass deine Decomposition für diesen Baustein falsch ist?

→ Sektion D deines Spec Sheets.


Beispiel: “Wenn Studierende, die ich klar als kompetente Korrelationsinterpretiererinnen einschätze, an dieser Teilaufgabe systematisch scheitern, dann ist Baustein 3 nicht das, was diese Aufgabe wirklich testet.”


Ohne diese Notiz bleibt das Spec Sheet eine plausible Hypothese ohne Bedingungen, unter denen du sie aufgeben würdest.

~3 Min. Falsifikation als Disziplin. Nicht “perfekte” Notiz, eine ehrliche.

Selbst-Tun vs. Zuschauen

Markiere jeden Baustein in deiner Sektion B mit einem Tag:

Faustregel: Faktenwissen, Begriffliches, Erklärungswissen sind meist Selbst-Tun. Hilfsschritte (Tabelle formatieren, Standardabschnitt schreiben) sind oft Zuschauen-erlaubt. Und: was bei einer Anfängerin Selbst-Tun ist, kann bei einer Fortgeschrittenen Zuschauen-reicht sein.

~5 Min in Eigenarbeit. Auf das Diagramm zeigen: links die Aktion verändert die Lernerin, rechts die Beobachtung lässt sie weitgehend gleich. Tags sind eine erste Diskussionsgrundlage, nicht endgültig. Wenn alle Bausteine Selbst-Tun sind, ist das ein normales Ergebnis.

Verpflichtung: in den nächsten zwei Wochen


Schreibe auf Papier:

  1. Eine konkrete Aufgabe deiner Lehre, an der du das Spec Sheet anwenden wirst. Nicht “ich werde nachdenken über…” sondern: diese spezifische Aufgabe.
  2. Ein konkreter Schritt (Spec anwenden / Aufgabenstellung anpassen / Studierenden-Konsequenz einbauen).
  3. Ein Datum, bis zu dem du es getan hast.


Erzähl es deiner Nachbarin, bevor du den Raum verlässt.

~2 Min. Konkretheit erzwingen. Spezifische Aufgabe, spezifischer Schritt, spezifisches Datum. Mündliche Zusage an Nachbarin als sozialer Commitment.


Danke.


Das Spec Sheet ist die durable Substanz deiner pädagogischen Arbeit mit KI. Werkzeuge ändern sich; was im Kopf einer Lernerin vorgeht, weniger schnell.

Verabschieden. Materialien-Hinweis in der Closing-Aktivitäten-Seite.
